# Mode: GitHub 开源项目

**触发信号:**
- URL 含 github.com/owner/repo
- 用户提到 "开源项目"、"GitHub 项目"、"项目 repo"
- 给出 npm package、PyPI 包、cargo crate 名

**推荐结构:** A(介绍型)

**推荐长度:** 3000-4500 中文字符

---

## 研究流程

### Step 1:抓 GitHub 主页(必做)

```
web_fetch("https://github.com/owner/repo")
```

提取以下关键信息:
- 项目英文名 + Tagline(repo description)
- README 完整内容
- Star / Fork 数(实时,不能用旧数据)
- License
- 主要语言(GitHub 自动识别)
- 最近 commit 时间
- 最新 release 版本
- 社区数据(Issues / PRs 数)

### Step 2:补搜中文资料(强烈推荐)

```
web_search("项目名 功能 特性 教程")
web_search("项目名 评测 对比")
```

中文博客通常有比 README 更详细的功能解释、使用截图、和同类的对比。

### Step 3:看 Releases(可选,适合活跃项目)

```
web_fetch("https://github.com/owner/repo/releases")
```

适合:
- 频繁更新的项目(看活跃度)
- 想强调"最新功能"的文章

### Step 4:看作者背景(可选,适合个人项目)

```
web_fetch("https://github.com/{author}")
```

或搜索作者的其他项目、博客、社交账号。

## 写作要点

### 1. 数据要新鲜

GitHub Star 数变化快。**用最新的**(刚抓的),不要引用旧博客里的数字。

### 2. License 要写对

常见 License:MIT / Apache 2.0 / GPL-3.0 / BSD / CC0
**不知道时去看 LICENSE 文件**,不要靠猜。

### 3. 区分"已实现"和"计划中"

README 里有时会写 "Coming soon" / "Roadmap"。
**这些功能不能当作"已有"写**。

### 4. 命令要从 README 抄

不要根据"印象"写安装命令。**复制粘贴 README 里的原始命令**。

### 5. 项目地址必须用代码块

```markdown
**项目地址:**

​```
https://github.com/owner/repo
​```
```

这样在公众号编辑器里能识别为可点击链接。

### 6. 标题模式建议

- 高 Star 项目(>10k):**模式 1(数据震撼型)**
- 大厂出品:**模式 3(权威背书型)**
- 痛点解决型:**模式 2(对比落差型)**
- 一人公司/独立项目:**模式 5(身份共鸣型)**

## 已知陷阱

### 陷阱 1:项目已死还在介绍

写之前一定查 last commit 时间。如果**超过 6 个月没更新**:
- 要么不写
- 要么文中如实说明"项目维护节奏已放缓"

### 陷阱 2:把名字相似的项目搞混

GitHub 上同名项目很多。**确保 URL 是用户给的那个**。

例如:Anthropic 官方的 Claude 和某个 fork 的 ClaudeXX 是不同项目。

### 陷阱 3:Fork 当原创

注意区分**原项目** vs **fork 项目**。如果用户给的是 fork,要在文章里说清楚。

### 陷阱 4:用户问"再来一篇"时不查最新数据

如果之前写过这个项目,**第二次写时 Star 数据可能已变**。要重新抓取,不要用旧数据。
