# Mode: GitHub 开源项目 v1.1

## 研究

优先读取：

1. README
2. repo metadata
3. License
4. Releases
5. 关键源码
6. Issues / Discussions（只在需要时）
7. 第三方资料（补充，而不是替代原始来源）

## 写作核心

不要按 Features 顺序写。

先回答：

> **这个项目真正解决的麻烦是什么？**

再选 3–5 个最值得写的设计。

## 必须寻找的信息增量

至少尝试：

- README 和源码是否一致？
- 有没有默认配置与宣传口径不同？
- 是否有看起来很强但条件有限的 benchmark？
- 哪个功能才是真正节省时间的？
- 它和同类工具是不是不同赛道？
- 当前最现实的限制是什么？

## Star 使用

Star 只是项目受关注程度的信号，不等于质量。

只有当 Star / 增长速度本身有故事时，才放标题。

## 推荐结构

```text
真实痛点
↓
项目是什么
↓
真正重要的 3–5 个设计
↓
源码 / 实现中值得注意的细节
↓
使用边界
↓
适合谁
↓
更大的产品 / 技术判断
↓
项目信息与来源
```

## 禁止

- README 中文翻译
- “XXk Star 所以一定好”
- 没运行就写“实测”
- Roadmap 写成已实现
- 把 fork 当原创
