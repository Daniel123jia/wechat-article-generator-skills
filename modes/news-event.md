# Mode: 新闻事件

**触发信号:**
- 新闻链接(科技媒体、官网公告、新闻稿)
- 用户提到"XX 发布"、"XX 公司宣布"、"XX 事件"
- 时事话题、行业动态、产品发布会
- 用户描述一个"事件"而非"东西"

**推荐结构:** B(事件型)

**推荐长度:** 2500-4000 中文字符

---

## 研究流程

### Step 1:确认事件本身(必做)

```
web_fetch(用户给的链接)
```

如果用户没给链接,用关键词搜:
```
web_search("事件关键词 + 时间")
```

### Step 2:多源交叉验证(必做!)

新闻最容易被歪曲。至少找 **3 个独立来源**:
- 官方公告(公司官网、官方推特/X)
- 主流媒体报道
- 中文媒体的中文报道

```
web_search("event keyword official announcement")
web_search("事件 官方 声明")
web_search("事件 中文 报道")
```

### Step 3:背景挖掘

理解这个事件的"为什么":
- 之前发生过什么 → 这次为什么会出现?
- 涉及的公司/人物的过往 → 他们一向是什么风格?
- 行业上下文 → 这事的位置在哪?

```
web_search("公司名 history background")
web_search("事件 影响 分析")
```

### Step 4:多方反应(可选,深度文章用)

```
web_search("事件 对手回应")
web_search("事件 用户反应")
```

## 写作要点

### 1. 时效性是命

新闻类内容**最忌过时**。
- 写之前确认事件还在"热"
- 文章中明确写出事件时间
- 如果是几天前的事,要回顾"到现在又发生了什么"

### 2. 区分"事实"和"解读"

**事实:** 官方宣布的、可验证的
**解读:** 媒体/分析师的看法

文章中要清楚标注:
- "据 XX 报道"
- "XX 公司在官方公告中表示"
- "分析师认为"
- "我个人觉得"

不要把解读当事实写。

### 3. 谨慎处理未经证实的信息

如果只是"传闻""有消息称"——
- 在文中明确标注是"传闻"
- 引用具体来源
- 不下定论

### 4. 政治/敏感话题特别小心

涉及国家、政治、宗教、争议人物等:
- 描述事实,不下道德判断
- 多方观点并陈
- 必要时直接绕开

### 5. 标题模式建议

- 戏剧性事件:**模式 10(故事型)**
- 大公司新闻:**模式 3(权威背书型)**
- 行业大事:**模式 1(数据震撼型)**
- 反共识事件:**模式 11(观点宣言型)**
- 福利/政策:**模式 9(福利紧迫型)**

## 已知陷阱

### 陷阱 1:依赖单一信源

很多新闻最初的报道是错的或夸大的。**至少 3 个来源交叉**。

### 陷阱 2:用旧标题党稿件

中文媒体常常用 1 年前的事改头换面再发。看清**原始信源的发布时间**。

### 陷阱 3:把"计划"当"现实"

公司宣布"将在 2027 年发布 XX",不等于已经发布了。
**已发布 vs 计划发布**要分清。

### 陷阱 4:翻译失真

英文新闻翻译成中文后常常变味。**英文原文优先**,翻译要谨慎。

### 陷阱 5:数字不准

融资额、用户数、市值等数字,不同媒体经常给出不同。
**以官方披露为准**,不行就找 SEC 文件、官方 IR 页面。
