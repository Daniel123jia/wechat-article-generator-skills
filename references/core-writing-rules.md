# 中文公众号写作核心规范

**所有模式共享的基本功**。无论你写 GitHub 项目、新闻、论文还是观点,这些规则**一律适用**。

---

## 一、读者画像

**目标读者画像:**
- 年龄 25-40 岁
- 中文技术圈、产品圈、创投圈
- 在通勤、午休、睡前刷公众号
- 平均阅读时长 2-4 分钟
- 手机屏幕阅读为主

**他们最讨厌:**
- 营销号腔(震惊!逆天!)
- 翻译腔(这是一个伟大的工具)
- 信息密度低(读完什么也没记住)
- 标题党(打开后内容货不对板)
- 鸡汤式收尾(让我们一起拥抱 XX)

**他们最喜欢:**
- 真诚的、有信息密度的内容
- 干货明确、能直接拿走的
- 有作者本人的判断和观点
- 节奏舒适(短句 + 长句交替)
- 有数据、有事实、有具体案例

## 二、语气基调

### ✅ 我们追求

| 维度 | 描述 | 实例 |
| :--- | :--- | :--- |
| **真诚** | 像和朋友聊天,不卖弄 | "做这件事最让人头疼的就是..." |
| **理性** | 给事实和判断,不夸大 | "8.1k Star 不是偶然,这背后是..." |
| **共情** | 站在读者位置 | "你是不是也遇到过..." |
| **干货密度** | 每段都有新信息 | 不写废话不灌水 |
| **节奏感** | 长短句交替 | 一段不超过 5 行 |
| **观点感** | 作者有自己判断 | "我个人觉得..."、"值得关注的是..." |

### ❌ 必须避免

| 类型 | 反面例子 | 为什么 |
| :--- | :--- | :--- |
| **营销号腔** | "震惊!这款工具竟然..." | 廉价、不专业 |
| **翻译腔** | "这是一个伟大的、令人惊叹的工具" | 不像中文母语者 |
| **导师腔** | "亲,你需要明白的是..." | 油腻 |
| **公文腔** | "本工具具备良好的扩展性" | 干瘪 |
| **过度专业** | "基于 transformer 架构的多模态预训练大模型..." | 把读者吓跑 |
| **饭圈用语** | "宝子们冲呀!神仙项目!" | 不适合技术内容 |
| **正确的废话** | "这是一个非常好的项目" | 没有任何信息量 |

## 三、句式与节奏

### 1. 短句 + 长句交替

**反面:**
> 这个项目是一款基于 SpringBoot、Apache Shiro、MyBatis、Thymeleaf 经典技术组合的后台管理系统,主要目的是让开发者注重专注业务降低技术难度从而节省人力成本缩短项目周期。

**正面:**
> 它是一款基于经典技术组合的后台管理系统。目的很明确——**让你专注业务,而不是和框架搏斗**。省人力、省时间、提质量。

### 2. 用对话感取代说明书感

**反面:**
> 该工具支持多种文档格式,包括 PDF、Word、图片等。

**正面:**
> 你扔进去一份 PDF、一份 Word、几张图片——它都能吃下去,然后告诉你里面写了什么。

### 3. 段落控制

- **一段不超过 5 行**(手机约 1 屏)
- **重要信息独占一段**
- **段与段之间用空行分隔**
- 写完 1 段问自己:这段加了新信息吗?没有就删

### 4. 善用反问、感叹、停顿

```
为什么这个项目能拿到 78k Star？

第一,它命中了真实的痛点——每个 AI 编码用户都踩过这些坑。
```

## 四、标点符号规范

### 中文标点优先

- 用 `,。;:?!`(中文)而非 `,.;:?!`(英文)
- 引号:`""''`
- 破折号:`——`(两个连用)
- 省略号:`……`

### 英文与数字之间加空格

- ✅ `这个项目获得了 78k Star`
- ❌ `这个项目获得了78k Star`

### 中英混排规范

- ✅ `Claude Code 是 Anthropic 出品的`
- ❌ `Claude Code 是 Anthropic出品的`

### 强调用 `**` 加粗

不要全段加粗,只加粗**关键句**或**关键词**。一段最多加粗 1-2 处。

### 感叹号克制

一篇文章最多 5-8 个感叹号。**标题最多 1 个**。

## 五、词汇选择

### 推荐使用

| 场景 | 推荐词 | 避免词 |
| :--- | :--- | :--- |
| 描述项目优点 | 扎实、靠谱、好用、舒服 | 完美、强大、卓越、震撼 |
| 描述使用感受 | 顺手、爽、丝滑、不费劲 | 极致体验、堪称完美 |
| 描述价值 | 解决了痛点、补齐了空白 | 颠覆了行业、改变了世界 |
| 描述数据 | 8.1k Star、月活 100 万 | 海量用户、超高人气 |
| 描述时间 | 2026 年 3 月、最近一周 | 近来、近期、近段时间 |
| 描述变化 | 涨了 / 降了 / 多了 / 少了 | 暴涨 / 崩跌 / 海量 / 寥寥 |

### 红词清单(必须避免)

- 震惊 → "让人惊喜的是"
- 逆天 → "出乎意料地好"
- 碾压 → "表现优于"
- 颠覆 → "打破了之前的常规"
- 革命性 → "带来了真正的变化"
- 王炸 → "够强 / 够猛"
- 神级 → 慎用,每 10 篇 1 次
- 屠榜 → "登顶 / 占据榜首"
- 万能 → 几乎不要用
- 完美 → "做得很好 / 做到位了"

### 句子开头变化

避免一直用"这个项目"、"它"、"该工具"。变化:

- 项目名(直接称呼)
- "作者..."
- "从仓库结构看..."
- "实际使用时..."
- "对开发者来说..."

## 六、数据呈现规范

### Star 数

- 1000-9999 → "X.Xk Star"(如 5.6k Star)
- 10000+ → "XXk Star"(如 78k Star)
- 100000+ → "XXXk Star"(如 491k Star)

### 时间

- 用具体日期:"2026 年 3 月 31 日"
- 不用模糊词:"最近"、"前段时间"
- 用具体时长:"3 分钟"、"约 1.5 秒"

### 引用原文

引用英文原文时,**英文原文 + 中文翻译**双呈现:

```markdown
> **The fastest repo in history to surpass 100K stars ⭐.**
>
> **GitHub 史上最快达到 10 万 Star 的项目。**
```

## 七、Emoji 使用规则

| 场景 | 是否用 emoji | 用什么 |
| :--- | :--- | :--- |
| 文章正文段落 | ❌ 不用 | — |
| 功能小节标题 | ✅ 用 | 🎯 🛠️ 🤖 📊 🔐 等(每节 1 个) |
| 信息表格 | ✅ 用 | 🏷️ ⭐ 📝 🔗 等(每行 1 个) |
| 列表项 | ⚠️ 谨慎 | ✅ ❌ ⚠️ 等(语义化使用) |
| 标题(全文最大的) | ⚠️ 通常不用 | 极少特殊场合 |

## 八、收尾语气

### ✅ 推荐风格

```
开源项目能火,往往不是因为技术最新最潮,而是因为真正解决了实际问题。

XX 就是这样一个项目。它的技术栈不是最炫酷的,它的界面不是最时髦的,
但它把一个 XX 系统需要的 90% 能力都做得扎实、易用、可维护。

8 年时间,8000+ Star,无数企业在生产环境中使用——这份成绩,值得每一
个 Java 开发者认真看一看。
```

### ❌ 避免的收尾

```
让我们一起拥抱开源,共建美好未来!
```

```
人生苦短,我用 Python!XX 项目值得每个程序员收藏!
```

```
未来已来,你准备好了吗?
```

### 收尾的 3 种安全模板

**模板 A:数据收束**
> 145k Star 的背后,是十年如一日的坚持,是一个人对"让更多人爱上开源"这件事的执着。如果你还没有订阅 HelloGitHub,今天就是最好的开始。

**模板 B:行业反思**
> 在一个"快餐式学习"盛行的时代,build-your-own-x 代表了一种**反潮流**的态度:学技术没有捷径,你必须亲手造一遍才算真正懂。

**模板 C:行动召唤(克制版)**
> 打开 build.nvidia.com,5 分钟后回来谢我。

## 九、互动收尾段(标准模板)

每篇结尾都用这个结构:

```markdown
> **互动话题**:「与文章主题强相关的开放性问题」?欢迎在评论区分享!

**觉得有用,点「赞」+「在看」,转发给身边「具体目标人群」!** 🙏
```

互动话题要**与主题强相关**,激发评论欲。

**反面:**
> 你怎么看 AI 的未来?

**正面:**
> 你已经领到 NVIDIA 的免费 API 了吗?最想用它跑哪个模型——GLM、Kimi、DeepSeek 还是 MiniMax?

## 十、文章长度参考

| 内容类型 | 推荐长度(中文字符) |
| :--- | :--- |
| GitHub 项目介绍 | 3000-4500 |
| 新闻/事件解读 | 2500-4000 |
| 推特帖子展开 | 2000-3500 |
| 学术论文解读 | 3500-5000 |
| 产品评测 | 3000-4500 |
| 教程指南 | 3000-5000 |
| 观点/思考文 | 2500-4000 |
| 工具/福利推荐 | 2500-4000 |

**极限范围:不超过 5500 字**。如果素材太丰富,**做减法**而非堆砌。

## 十一、写完自检 Checklist

每篇文章交付前,都过一遍:

### 真实性
- [ ] 所有数据都经过验证(没编造)
- [ ] 项目状态准确(还在维护吗?)
- [ ] 作者/机构信息正确

### 表达质量
- [ ] 没有翻译腔
- [ ] 没用红词("震惊"、"逆天"、"碾压"等)
- [ ] 中英文之间有空格
- [ ] 标点全部中文标点
- [ ] emoji 只用在小节标题和表格
- [ ] 加粗用得克制

### 节奏
- [ ] 一段不超过 5 行
- [ ] 短句长句交替
- [ ] 段落之间有空行

### 内容
- [ ] 有共鸣式开头
- [ ] 主体每段都有新信息
- [ ] 收尾不鸡汤
- [ ] 互动话题与主题强相关

### 输出
- [ ] 文件名格式正确
- [ ] 保存到正确目录
- [ ] 多素材时每个独立成文

### 长度
- [ ] 在推荐区间内
- [ ] 没有为凑字数而灌水

通过自检的文章,才能交付。
