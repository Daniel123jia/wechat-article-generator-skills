# 公众号文章结构 v1.1

结构是叙事工具，不是固定目录。

## A. GitHub / 工具类

推荐：

```text
1. 一个真实问题
2. 为什么现有方式麻烦
3. 项目出现：一句话是什么
4. 真正值得看的 3–5 个设计
5. 源码 / Benchmark / 真实边界
6. 谁适合用
7. 我认为它真正重要的地方
8. 来源 / 项目信息
```

## B. 学术论文类

```text
1. 为什么这个问题值得关心
2. 论文真正提出了什么
3. 关键方法：只讲决定性的部分
4. 最有解释力的 2–4 组证据
5. 论文能证明什么、不能证明什么
6. 我的解读 / 对实际研究的启发
7. 更大的趋势
8. 论文信息与来源
```

## C. 新闻 / 事件

```text
1. 发生了什么
2. 为什么现在值得关注
3. 关键背景
4. 真正影响最大的 3 件事
5. 不同视角 / 不确定性
6. 对目标读者意味着什么
7. 后续观察点
```

## D. 观点

```text
1. 一个具体现象
2. 我的核心判断
3. 证据 1
4. 证据 2
5. 反方最强观点
6. 判断成立的边界
7. 对读者的实际意义
```

## E. 教程

```text
1. 最终能完成什么
2. 前置条件
3. 3–7 个真实步骤
4. 第一个跑通结果
5. 常见坑
6. 什么时候不适合这样做
```

## F. 故事 / 人物 / 视频台词

```text
1. 最有张力的一句话 / 场景
2. 主角和背景
3. 3–5 个真正有价值的判断
4. 逐点展开
5. 把观点放回现实场景
6. 我的延伸
7. 收束
```

## 原则

- 不要求每篇都带信息表格；
- 不要求每篇都有副标题引述；
- 不要求每篇都有互动话题；
- 不要求每篇都 10+ 小节；
- 用户明确要求某种结构时，优先按用户要求。
