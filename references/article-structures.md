# 文章结构变体集合

不同类型的素材适合不同的结构骨架。这里收录了常用的几种结构,以及每种结构适合的素材类型。

各 mode 文件会推荐使用哪种结构,但有时根据素材调整也很正常。

---

## 结构 A:介绍型(标准长文)

**适用:** GitHub 项目、产品评测、工具推荐

```
1. 标题(数据/特征 + 项目名 + 价值定位)
2. 副标题引述(项目核心定位)
3. 痛点钩子(读者熟悉的困境)
4. 项目简介(它是什么 + 基本数据)
5. 核心功能详解(4-7 节,占文章 30-40%)
6. 实际使用场景(3-5 个具体场景)
7. 同类对比(可选,有清晰竞品时)
8. 适合谁用 / 不适合谁用
9. 写在最后(行业反思 + 升华)
10. 信息表格
11. 互动话题 + 转发 CTA
```

**长度:** 3000-4500 字

---

## 结构 B:事件型(新闻/动态)

**适用:** 新闻事件、行业大事、产品发布、爆款消息

```
1. 标题(事件主体 + 影响 / 反转点 / 戏剧性)
2. 副标题引述(事件最关键的事实)
3. 事件还原(发生了什么、谁、何时、何地)
4. 背景脉络(为什么会发生 / 之前的故事)
5. 关键细节展开(2-4 节深入)
6. 影响评估(对谁 / 行业 / 普通人意味着什么)
7. 不同视角(可选,各方反应)
8. 你该关心的什么(读者的实操层面 take-away)
9. 写在最后(更深层的反思)
10. 信息时间线表格(可选)
11. 互动话题 + 转发 CTA
```

**长度:** 2500-4000 字

---

## 结构 C:观点型(思考文)

**适用:** 行业观察、个人观点、深度思考

```
1. 标题(观点本身 / 反直觉判断)
2. 副标题引述(观点的精华句)
3. 引子(一个具体场景或现象)
4. 提出观点(我认为 X)
5. 论证 1(数据/事实/案例)
6. 论证 2(数据/事实/案例)
7. 论证 3(数据/事实/案例)
8. 反方观点的预判(承认对立观点的合理性)
9. 我为什么仍坚持这个观点
10. 这个观点对你意味着什么(读者的 take-away)
11. 写在最后(开放式收束 / 留给读者思考)
12. 互动话题 + 转发 CTA
```

**长度:** 2500-4000 字

---

## 结构 D:解读型(论文/研究)

**适用:** 学术论文、研究报告、深度文档

```
1. 标题(论文主张 / 出乎意料的结论)
2. 副标题引述(论文最关键的结论)
3. 痛点钩子(为什么这个问题重要)
4. 这篇论文是什么(机构 + 作者 + 发表地点)
5. 核心问题(它要回答什么)
6. 研究方法(它怎么做的)
7. 关键发现(它发现了什么,3-5 点)
8. 直观解释(用读者能理解的类比)
9. 局限性(论文自己承认的 / 你看到的)
10. 对实际工作的启发
11. 写在最后(超越论文本身的反思)
12. 论文信息表格(arXiv ID、作者、机构、链接)
13. 互动话题 + 转发 CTA
```

**长度:** 3500-5000 字

---

## 结构 E:教程型(How-to)

**适用:** 操作步骤、技术教程、保姆级指南

```
1. 标题(明确告诉读者学完能做什么)
2. 副标题引述(教程的承诺,几分钟搞定)
3. 这个教程能让你做什么(明确的成果)
4. 前置条件(你需要准备什么)
5. Step 1:[第一步]
6. Step 2:[第二步]
7. Step 3:[第三步]
   ...(步骤数视复杂度,通常 3-7 步)
N. 验证 / 测试 / 第一个跑通的例子
N+1. 常见问题(踩坑提示)
N+2. 进阶玩法(可选)
N+3. 写在最后
N+4. 信息表格 + 互动 + CTA
```

**长度:** 3000-5000 字

---

## 结构 F:推特/X 帖子展开型

**适用:** 把推特上某个引爆讨论的帖子展开成长文

```
1. 标题(帖子作者 + 帖子核心 + 引爆点)
2. 副标题引述(帖子最关键的一句)
3. 这条推文为什么火(引发的讨论体量、转发数等)
4. 推文原话(完整呈现 + 翻译)
5. 作者背景(这个人是谁 / 他为什么有发言权)
6. 帖子的真正含义(把社交媒体的简短表达展开)
7. 评论区精彩反应(挑 3-5 条有信息量的回复)
8. 这件事的更大背景(行业脉络)
9. 对你的启示
10. 写在最后
11. 互动话题 + 转发 CTA
```

**长度:** 2000-3500 字

## 结构 G:福利羊毛型

**适用:** 免费 API、限时福利、薅羊毛攻略

```
1. 标题(谁送 + 送什么 + 价值感 / 紧迫感)
2. 副标题引述(关键福利参数)
3. 大背景(为什么今天值得抓住这个福利)
4. 福利是什么(给谁送 + 为什么送 + 值多少)
5. 关键参数表(额度 / 期限 / 限制)
6. 领取教程(分步骤,每步具体操作)
7. 使用方式(领到后怎么用,接入哪些工具)
8. 常见踩坑提醒(必须看!)
9. 适合谁用 / 不适合谁用
10. 写在最后(行业洞察 + 行动催促)
11. 信息表格
12. 互动话题 + 转发 CTA
```

**长度:** 2500-4000 字

## 结构 H:对比测评型

**适用:** 多个产品/工具/方案的对比

```
1. 标题(N 个 XX 横评 / 对比)
2. 副标题引述(对比维度 + 最终推荐)
3. 为什么需要这次对比(读者的真实困惑)
4. 参选产品介绍(逐个简单介绍)
5. 对比维度说明(我们看哪几个维度)
6. 维度 1 横向对比
7. 维度 2 横向对比
   ...(维度数 3-6 个)
N. 综合评分表(可选)
N+1. 不同场景下的推荐(预算敏感→A,追求体验→B...)
N+2. 写在最后
N+3. 信息表格 + 互动 + CTA
```

**长度:** 3500-5000 字

---

## 结构 I:故事型

**适用:** 创业故事、人物背景、戏剧性事件

```
1. 标题(戏剧化的事件本身)
2. 副标题引述(故事最具冲突的一句)
3. 一个具体场景作为开头(时间、地点、人物)
4. 这是谁(主角介绍)
5. 故事是怎么开始的(起因)
6. 中间发生了什么(经过,关键转折)
7. 结果(发展或当下)
8. 这个故事告诉我们什么(意义)
9. 写在最后
10. 互动话题 + 转发 CTA
```

**长度:** 2500-4000 字

## 选择哪种结构?

### 决策树

1. **素材是开源项目/产品/工具** → 结构 A(介绍型)
2. **素材是新闻/事件** → 结构 B(事件型)
3. **素材是观点/想法** → 结构 C(观点型)
4. **素材是论文/研究** → 结构 D(解读型)
5. **素材是步骤型内容** → 结构 E(教程型)
6. **素材是推特/X 帖子** → 结构 F
7. **素材是免费/福利** → 结构 G
8. **素材是多个东西对比** → 结构 H
9. **素材有戏剧性故事** → 结构 I
10. **不确定** → 默认结构 A,根据素材调整

### 灵活原则

- 结构是骨架,**不是教条**。某些节如果素材不支持,可以省略
- 某些节如果素材丰富,可以拆得更细
- 节的顺序可以微调,但**开头钩子和结尾收束**必须有
- 信息表格 + 互动话题 + CTA **永远在最后**

## 通用元素(跨结构)

无论用哪种结构,以下三个元素**所有文章都必须有**:

### 1. 主标题
- 25-45 字
- 包含具体数据/特征
- 中文标点
- 最多 1 个感叹号

### 2. 副标题引述
- 紧跟标题
- 用 `>` 引用块
- 一两句话精华提炼

### 3. 信息表格(置于结尾)
- 用 markdown 表格
- 每行一个 emoji + 字段 + 值
- 5-12 行为宜
- 让读者一眼能记住核心信息
